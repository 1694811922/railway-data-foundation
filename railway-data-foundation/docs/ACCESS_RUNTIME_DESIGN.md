# V0.3运行时授权设计

本阶段实现REST共享访问，沿用已确认关系和策略，不把业务行传入Foundation。以下为实施设计，完成标记以实际测试与联调为准。

## 身份与凭据

- 管理员向已启用的需求方签发256位安全随机调用凭据，格式`rdf_`加43位Base64URL随机串。签发响应仅一次展示，列表/详情不回显；数据库只保存SHA-256摘要，不保存明文。随机高熵凭据不是用户口令，不接收客户端自设令牌。
- 凭据独立保存名称、所属需求方、有效期、状态、版本及签发/撤销历史。只能撤销，不能恢复；需要新凭据时重新签发。记录原型管理员标签，仍不代表管理员已进行服务端登录认证。
- 调用方使用`Authorization: Bearer ...`、`X-Relationship-Id`和`X-Capability-Id`。需求方身份从凭据推导，不接受请求自报主体编号作为认证。
- Provider向Foundation发送控制校验时，还携带运维配置的`X-Provider-Token`，防止普通调用方冒充执行服务。该服务间密钥只在被忽略的环境配置中保存，本机首次生成后复用，不进入前端、数据库或调用指引。

## 每次请求的校验

Provider在读取业务源之前发起`POST /api/v1/access/check`；请求只包括关系/能力编号、期望字段、过滤字段名称和时间边界，不包括业务行或过滤值。Foundation认证凭据，并检查需求方与提供方、关系确认/启用/有效期、资源/来源、能力及策略。

缺省返回字段采用策略允许字段；明确请求字段必须为其非空子集。用于过滤的字段也必须被策略允许，避免利用未授权字段推测信息。缺省时间边界采用策略边界；显式超出范围拒绝，不能把越权条件静默截断。授权有效期与数据时间范围分别校验。

Foundation返回允许或拒绝，以及字段、时间条件、来源和版本等控制元数据。Provider核对响应归属、支持字段、来源、区间和有效期，再使用字段白名单及绑定参数直连Source。`container_event`只支持既有12个字段及3个时间类型字段，未知字段/时间字段默认拒绝，不接收任意SQL、表名或目标地址。

时间条件通过带时区ISO8601传递并按UTC决策。源业务DATETIME按Provider配置的固定时区偏移解释，默认`+08:00`；连接会话时区与之保持一致，SQL过滤含起点、不含终点。治理表时间仍为UTC。

## 拒绝与失效

未认证、过期/撤销凭据、未确认/暂停/撤回/过期关系、越权字段或时间、停用主体/资源/来源/能力均拒绝。底座超时、异常、重定向或响应错配也拒绝，不查询业务行。旧的仅携带能力编号的REST查询不再放行；没有关闭授权的兼容开关。

初版每次请求读取当前治理状态，不缓存允许决策。已通过检查的在途请求可能完成；撤销提交后新的校验会看到当前状态。后续若增加缓存或流式长连接，先定义撤销传播机制。

HEAD探测仅检查表和权限，不返回业务行，继续用于能力验证。Kafka生产的HTTP触发接口限定服务间密钥操作；普通调用凭据不直接授予该接口权限。Kafka Topic消费ACL、CDC和只读模板权限执行仍不在此REST阶段，不能宣称全部能力已受策略保护。
