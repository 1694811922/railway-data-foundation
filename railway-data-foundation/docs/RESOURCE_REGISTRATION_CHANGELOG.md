## 操作流程

扫描工作台选择表 → 打开资源登记弹窗 → 核对指定任务和候选表 → 人工填写业务信息 → 保存草稿 → 核对并发布 → 登记能力。

| 环节 | 当前行为 |
|---|---|
| 入口检查 | 任务编号、来源编号、模式和表名必须是完整单值；拒绝缺失、重复参数数组和超长值 |
| 来源核对 | 调用既有任务详情与候选表接口；必须为指定来源的成功任务，模式和表名必须唯一匹配该任务候选表 |
| 权威名称 | 来源名称从任务响应读取，不采信网址中的sourceName；表名、模式和来源只读 |
| 读取状态 | 显示核对中、失败或已核对；失败可单独重试，未核对不能填写/保存，不借用演示扫描结果 |
| 人工确认 | 核对成功展示任务编号、表说明、字段数及估算记录数；业务名称、描述、责任单位、安全等级与更新方式仍由人工填写 |
| 重复登记 | 已读取目录中同一来源/模式/表已登记时阻止重复保存，提供“查看已有资源”入口 |
| 重新进入 | 取消弹窗后，网址仍有扫描入口时可点击“继续登记所选表”；待旧操作结束后可主动重新核对 |
| 编辑 | 绑定当前资源、版本、状态、数据模式及不可变来源；当前记录变化时要求重新打开 |
| 提交 | 保存和发布互斥；输入、取消/关闭、刷新和冲突操作锁定，重复提交被拦截；提交体只含原约定字段 |
| 失败 | 保留输入，不模拟成功；响应丢失时不自动重发，刷新确认实际状态 |
| 旧响应 | 切换扫描入口或退出页面后，旧核对结果不填入新表单，旧保存不导航，旧发布不刷新新入口 |
| 参数边界 | 与现有后端长度及TABLE类型一致；来源/模式/物理表不能改为其他扫描表 |

只使用现有`GET /scan-tasks/{id}`、`GET /scan-tasks/{id}/tables`、资源目录和写入接口。指定任务用于前端入口核对，保存请求没有新增task_id参数；后端仍按现有逻辑采用该来源/模式/表的最新成功扫描来复制字段，不保证固定为入口任务快照。重复提示只覆盖已读取目录范围（最多5,000项），后端唯一约束仍负责最终判定。前端版本绑定不替代服务端并发控制。
