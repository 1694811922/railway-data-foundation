# Kafka 订阅权限执行交付记录

日期：2026-10-10。范围沿用用户明确选择的整主题授权，完成专属身份、精确读取权限、一次性凭据、停止/撤回及到期/依赖失效撤权。不开发需求方业务服务、消费计量或 CDC。

## 本轮实现

- V13 新增执行记录表及中文注释，审批状态与实际执行状态分开；审批、执行、领取历史共用当前版本保护。
- 每轮独立随机 SCRAM-SHA-512 身份；只授予指定主题 READ/DESCRIBE、固定消费组 READ。停止并核对后才可创建新身份，不复用其他申请账号。
- 先提交数据库意图，再执行 Broker；集群编号固定且实际核对，错配拒绝操作。结果入库失败保留意图恢复，外部失败转撤权补偿，不伪装成功。
- 领取前重新核对治理条件及实际身份/ACL，只返回一次密码，清除密文并禁止缓存。普通查询/历史无密码，前端关闭/离开即清除，不写浏览器存储。
- 独立定时协调器处理到期、双方主体/来源/资源/能力失效、未完成及失败意图；每轮10项，默认5秒，已撤权后停止处理。
- 中文页面区分审批与权限，“订阅操作”配置/领取/停止/重试，详情包含实际核对时间、脱敏原因和操作历史；能力详情可进入对应主题授权。

核心文件见 [执行与使用指南](KAFKA_SUBSCRIPTION_EXECUTION.md)，接口见 [KAFKA_SUBSCRIPTION_API.md](KAFKA_SUBSCRIPTION_API.md)。

## 尚未完成的部分

本机没有常驻 Kafka，正常开发配置默认不执行权限，按指南提供真实集群及独立管理员后可使用。真实隔离联调通过不表示生产部署完成。

静态 Broker ACL 没有原生租期；协调器有延迟，控制服务停机/关闭执行时可能保留访问，不能保证即时中断或收回客户端缓冲。运维应先核对全部实际撤权再停止控制服务。多集群/多主题动态路由、可信管理员登录、消费侧计量、CDC、无损采集尚未实现。当前固定 Provider 与已配置主题的原型范围不扩大。
