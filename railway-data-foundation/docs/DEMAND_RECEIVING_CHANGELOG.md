# 2026-10-13 需求方真实数据接收与落库

本轮按用户明确授权，将需求方接收从CLI观察示例扩展为正式独立服务与统一前端工作台。完成真实Kafka持续消费、独立MySQL落库、消费位置提交、持久恢复及消息查询。底座仍只保存治理元信息和技术摘要，不代理或保存业务消息。

## 已实现行为

- 每授权一个任务；连接参数、主体、精确主题和消费组来自真实授权，不信任页面指定的身份或目标。
- 需求方本主体可以管理任务和查询数据；管理员、提供方及其他需求方主体不能使用消息接口。列表与总数按主体过滤。
- 独立接收服务使用已签发的Kafka专属密码和技术令牌，不使用源库密码、平台登录密码或Broker运维账号。
- 原始消息键、值、消息头、时间及位置完整保存，支持JSON、文本、二进制、NULL及重复消息头。
- 消息、检查点和技术补报记录同事务提交，之后提交Kafka位置。失败可重读，按位置幂等，主题重建或重复位置内容不一致时阻塞。
- 任务在页面关闭、退出登录及服务重启后继续或恢复。初始起点只确定一次，恢复使用数据库检查点，不静默跳过被清理的历史。
- 密码与技术令牌用独立需求方密钥加密保存。一次性前端转交最多保留一分钟，取走、关闭、退出或身份变化即清除，不写浏览器存储。
- 每批落库前及空闲每3秒核验治理；核验故障暂停，撤权、到期等失效阻塞。已交付数据保留，不声称追溯撤回。
- 有限退避重试、人工恢复、停止后凭据更新、同一数据库单实例锁；最多4个并行任务。
- 连接会话固定UTC，使默认接收时间与摘要补报调度时间一致，避免本机时区造成延迟。
- 接收进程使用显式环境白名单，实际验证没有继承其他服务秘密。日志为UTF-8文件轮转，关闭可能打印业务响应的调试输出。
- 启动构建关闭集成测试夹具开关，集成测试类强制目标测试库，避免继承测试环境误写运行库；先前临时夹具均已清理。

## 使用与限制

操作见 [使用指南](DEMAND_RECEIVING_GUIDE.md)，协议见 [接口说明](DEMAND_RECEIVING_API.md)。登录需求方后进入“数据接收”；必须先取得本主体有效Kafka订阅凭据。账号密码保持原样，不创建默认通用账号或密码。

本轮支持通用接收表中的真实交付，不包含具体业务表映射、CDC、源表自动生产消息、多实例高可用或跨Kafka/MySQL全局恰好一次。原广州港示例源仍为项目模拟记录；测试使用模拟源内容进行真实传输与落库，不宣称获取了真实港口生产数据。Windows Kafka仍为本机实验环境，不据此宣称稳定生产部署。
