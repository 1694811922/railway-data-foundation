# V0.5 第一小阶段交付：外部 REST 接入

日期：2026-10-09。

## 交付结果

外部调用方可读取能力调用说明，通过需求方令牌与共享关系/能力编号访问现有提供服务，顺序分页处理允许字段内的业务数据。实际联调覆盖成功、越权、暂停、恢复及撤销，并核对提供侧自动审计、追踪和分钟计量。范围限定统一数据底座接入与联调，不开发独立需求方业务服务。

## 验收证据

- 客户端 **16 项通过**：目标地址与凭据隔离、重定向拒绝、HTTP/业务码异常、响应字段/页大小/1 MiB边界、顺序分页、短页结束、页数上限、超时不重试、取消不交付晚到页及回调失败停止。
- 完整后端 **113 项通过**（Foundation 90、Provider 23），0失败、0错误、0跳过。
- 前端 **107 项通过**，`npm run build` 成功；既有包体大小提示仍存在，无构建错误。
- 实际接入验证：允许字段三页返回 **7/7/6，共20条**；策略内时间范围返回1条；越权字段/时间及暂停关系403；恢复后允许；撤销凭据后401；实际 CLI 只输出数量/追踪编号并标识页数上限。
- 一次最终验证共 **11 次请求、26条共享记录**（包括不同场景的重复读取），不是26条独立源记录；成功共享响应体共2145字节。逐请求与真实摘要核对，分钟调用/记录/字节总量一致，每次唯一追踪，不含令牌或业务值。
- PowerShell启动包装脚本实际调用通过，临时环境变量恢复。联调子进程补齐Windows脚本执行参数和命令扩展环境后最终重跑通过；此前失败轮次不计为验收通过。
- 联调前后资源版本、字段业务属性、能力与已确认策略保持不变；关系状态与凭据在临时测试配置上有明确操作。
- 浏览器 `test:telemetry-live` 通过：真实审计详情、治理版本、追踪跳转、分钟统计及读取失败/旧响应隔离。界面沿用既有页面，无新业务页面。
- 临时来源、资源、共享主体均已清理；源 `container_event` 保留20条，开发库仍V11。真实运行摘要保留作为历史证据。

本机日志与安全摘要位于被忽略的 `.runtime/v05-client-tests.log`、`v05-backend-tests.log`、`demand-rest-live.log`、`demand-rest-verification.json`；前端证据位于 `foundation-web/.runtime/v05-web-tests.log`、`v05-web-build.log`、`v05-telemetry-browser.log`。样例业务数据仍是广州港场景模拟事件，不是生产数据。

## 使用及后续

运行方法见 [外部 REST 接入规范](DEMAND_REST_INTEGRATION.md)。前端仍通过原“共享治理”和“运行监管”页面管理、核对；示例在 VS Code 终端执行。

V0.5 第一小阶段完成，不代表 V0.5 全部完成。下一步先设计 Kafka Broker 权限如何执行，再推进共享授权/状态联动与最小订阅验证，最后接入 CDC。当前不包含独立需求方服务、业务持久化、消费侧上报、多节点鉴权、完整分布式追踪、自动重试或恰好一次消费。
