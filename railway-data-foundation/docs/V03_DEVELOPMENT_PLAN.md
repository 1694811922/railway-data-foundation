# V0.3 共享治理开发计划

2026-10-04用户明确“恢复V0.3开发”，此前暂停要求结束。以《统一数据底座需求说明书》R14–R18为依据，保持一个管理员管理与确认，提供方、需求方作为业务主体登记，不新增三个独立门户。

## 开发顺序与验收

| 阶段 | 实施内容 | 验收条件 |
|---|---|---|
| 1 共享主体 | 提供方/需求方登记、查询、编辑、启停、唯一业务编码、版本冲突检查、中文管理页 | 数据持久保存；重复编码、非法角色、旧版本被拒绝；登记不产生共享权限 |
| 2 关系与策略 | 绑定提供方、需求方、已发布资源和具体能力；用途、有效期、允许字段与时间范围；管理员确认 | 资源/能力归属一致；字段存在于该资源；未确认关系不可启用；记录操作人、时间、原因和版本 |
| 3 可信身份与访问校验 | 定义并验证调用方身份凭据；Foundation只返回治理决策；Provider执行字段投影和时间限制 | 默认拒绝；不能仅凭自报主体编号访问；停用、过期、撤销、控制服务故障拒绝新的请求；不把业务行传入Foundation |
| 4 联调与演示 | 共享关系、策略中文页面，允许/拒绝场景，原链路回归 | 授权请求成功；越权字段、超出时间、过期和撤销均失败；有可复核的状态与结果 |

阶段1至3及REST允许/拒绝联调已实现：共享主体、关系/策略确认、调用凭据、Foundation决策、Provider字段投影和时间限制，中文管理与调用验证页。V9已在开发库及独立测试库运行，完整后端76项测试通过；真实浏览器验证授权成功、字段/时间拒绝、关系暂停/撤回及凭据撤销，原REST启停回归通过。Kafka消费端权限、CDC运行时和服务端管理员登录不在本阶段交付范围，不能因REST授权完成宣称这些机制已支持。

## 模型与业务流程

```mermaid
flowchart LR
  A[登记提供方与需求方] --> B[选择已发布资源及具体能力]
  B --> C[定义用途、字段、时间和有效期]
  C --> D[管理员确认共享关系]
  D --> E[启用关系及策略]
  E --> F[验证可信调用方身份]
  F --> G[底座返回允许或拒绝决策]
  G --> H[提供服务执行权限限制并直接读取源库]
```

共享主体是业务身份目录，与`source_system`的数据库连接配置是不同概念。一个提供方可管理多个来源，但本轮不擅自建立来源归属关系。主体业务编码、角色登记后不变；主体编号随机生成，不是密码、令牌或可信身份声明。已停用且未被共享关系引用的主体可删除；被关系引用的主体保留稳定标识与历史。

## 后续设计约束

- 共享关系必须同时绑定资源、能力和双方主体，不能仅按资源“全量放行”。主体停用也需进入后续访问校验的拒绝条件。
- 策略字段明确列举，时间范围绑定经人工确认的时间字段；调用时缺省字段只能使用允许字段，不能返回全部字段。输入校验与Provider执行必须一致。
- 关系状态按草稿、待确认、已确认/启用、暂停、撤销明确转移规则；启用必须有确认记录。使用乐观锁避免并发覆盖，状态记录与变更同一事务。
- 调用身份使用随机256位Bearer令牌，数据库只存摘要，签发时仅展示一次；接口查询不回显令牌，前端不持久化。不能把请求头主体编号当成已认证身份。详见[访问接口](ACCESS_API.md)。
- REST先完成字段与时间约束。Kafka权限应作用于主题或受控分发，不能假称普通主题已实现逐字段过滤；CDC最后接入。
- 初版每次访问读取当前治理状态，不缓存允许决策；后续若引入缓存或长连接，需要先定义失效、撤销传播与最大延迟。
- Foundation只保存治理信息；Provider拒绝时不查询业务行，允许时直连源库。联合校验保留V0.2能力启停检查；能力可用或关系启用仍需配合有效调用凭据，不代表匿名放行。
- 当前管理页面仍为本机原型演示入口，没有后端管理员身份认证，不作为生产系统对外部署。

接口说明见[共享主体接口](SUBJECT_API.md)与[关系及策略接口](SHARING_API.md)。实际测试记录见[测试记录](TESTING.md)，后续只在验证后更新完成状态。
