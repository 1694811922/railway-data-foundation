# 接收数据下载与导出

## 页面操作

需求方登录后进入 **数据接收 → 查看数据**。

- 列表 **下载消息**：下载一条完整消息JSON，包括主题、分区、位置、消息键、消息内容、消息头及时间。
- **查看内容 → 下载内容**：按原始字节下载内容；合法UTF-8 JSON为`.json`，普通UTF-8文本为`.txt`，非UTF-8内容为`.bin`。内容不重新格式化、不修改字节。
- **查看内容 → 下载完整消息**：包含元信息的JSON文件，可保留空值与空字节的差别。空值消息不提供“下载内容”，应下载完整消息。
- **导出筛选结果**：按当前主题、分区和接收时间范围导出全部符合条件的已落库消息，不限于当前页。格式为`.jsonl`，每行一个完整消息对象；最多10000条或50MiB，超限需缩小范围，不截断成成功文件。
- **取消下载**：取消尚未完成的文件请求。关闭数据面板、退出或切换身份会取消请求并丢弃晚到结果；已经保存到本机的文件不能远程收回。

接收时间范围为左闭右开。导出以请求时数据库读取快照为准，准备期间新落库消息不混入文件。行按落库消息编号升序排列。没有匹配消息时明确提示，不生成虚假成功文件。

JSONL示意：

```json
{"message_id":1,"topic":"example.topic","partition_id":0,"message_offset":0,"message_key":{"encoding":"UTF8","content":"key","bytes":3},"message_value":{"encoding":"UTF8","content":"{\"value\":1}","bytes":11},"headers":[]}
```

这里仅说明格式，不代表实际数据。完整文件还有任务/授权、实际主题身份、时间戳、字节数及内容摘要等既有存储字段。`encoding`为UTF8、BASE64或NULL；重复消息头保留为有序数组，头值保留原Base64或null，不合并为字典。

## 服务与权限

下载直接走独立 `/demand` 通道至需求方服务18082，不经底座后端传输文件。底座仅核验登录身份，不接收业务消息正文。

仅已登录且主体有效的需求方可下载本主体任务中的消息。管理员、提供方和其他需求方无权下载。开始准备前校验身份和归属，文件准备完成后再次核验登录；失效时不返回附件。Kafka撤权后，已合法落库的本主体历史数据仍可按原规则查询和下载，不重新连接Kafka或重新申请生产数据。

不将文件内容、密码或技术令牌写入日志或浏览器持久存储。浏览器临时Blob仅用于保存文件；文件下载后由用户妥善管理。导出不修改任务版本、接收检查点或消息记录。

## API

| 接口 | 行为 |
|---|---|
| `GET /api/v1/receiving-tasks/{id}/messages/{message}/download?format=content` | 下载原始内容，默认格式 |
| `GET /api/v1/receiving-tasks/{id}/messages/{message}/download?format=record` | 下载完整消息JSON |
| `GET /api/v1/receiving-tasks/{id}/messages/export` | 导出筛选后的完整消息JSONL |

导出支持`topic`、`partition`、`from`、`until`，不接受主体、角色、文件路径或源数据库地址。成功返回附件二进制流，附带`Content-Disposition`、`Content-Length`、`X-Download-Bytes`和`X-Export-Count`；失败仍返回`{code,message,data}`。前端核对实际Blob字节数和安全文件名，截断或残缺响应不保存为成功。

401为未登录/登录失效，403为越权，404为消息不存在，400为输入不合法、空结果或空值消息无内容；413为条数/大小/准备时间超限，429为已有文件准备或传输，503为准备失败。失败不自动重试。

## 实现限制

每个接收服务同时准备或传输一个下载文件；数据库按只读一致快照流式读取，不一次加载所有消息。为在发送HTTP附件前确认文件完整性，文件先写入需求方服务所在主机的私有临时目录，准备最多15秒，再流式传输；成功、失败或客户端断开后清理。清理被文件系统暂时阻止时，服务退出时重试删除。

此次是同步有界下载，没有后台导出任务、CSV/Excel业务列映射、断点续传或批量ZIP。当前源仍为模拟业务记录，接收、存储及下载通过真实服务完成。
