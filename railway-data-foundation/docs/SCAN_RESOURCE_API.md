# 元数据扫描与资源登记接口（V0.1）

所有接口以 `/api/v1` 为前缀，使用 `{code,message,data}` 响应。需先按 [数据源接口](SOURCE_API.md) 动态登记 MySQL 连接元信息和加密凭据；旧环境变量引用保持兼容。

前端表与字段的10/20/50项分页在完整读取现有结构接口后进行，不增加后端分页或业务行查询。字段接口当前不返回任务/表归属列，前端依靠请求上下文隔离旧响应，并在归属列出现时校验；不能将这种校验描述为后端字段快照验证。扫描返回任务必须与请求来源/模式一致；切换任务或退出后只忽略旧前端结果，不取消已执行的后端扫描。

| 方法与路径 | 作用 |
|---|---|
| `POST /sources/{sourceId}/scan` | 同步扫描该数据源，返回任务状态 `SUCCESS` 或 `FAILED` |
| `GET /scan-tasks?limit=50&offset=0` | 最近任务列表 |
| `GET /scan-tasks/{taskId}` | 任务详情及安全失败原因 |
| `GET /scan-tasks/{taskId}/tables` | 候选表、注释、字段数及估算行数 |
| `GET /scan-tasks/{taskId}/tables/{tableName}/fields` | 字段技术元数据 |
| `DELETE /scan-tasks/{taskId}` | 删除已结束且未被资源引用的任务及其结构元数据 |
| `POST /resources` | 指定`scan_task_id`，从所选成功扫描的表创建草稿资源 |
| `GET /resources?limit=50&offset=0` | 资源目录 |
| `GET /resources/{id}` | 资源详情 |
| `PUT /resources/{id}` | 携带读取时的`version`，更新业务信息，不允许修改来源、扫描绑定及物理表 |
| `POST /resources/{id}/publish` | 发布草稿资源，返回 Resource ID 和新版本 |
| `DELETE /resources/{id}` | 删除未关联能力的草稿资源及其字段元数据 |
| `GET /resources/{id}/fields` | 查看资源字段 |
| `GET /resources/{id}/versions?limit=20&offset=0` | 已留存版本列表，返回`items,total`，倒序分页 |
| `GET /resources/{id}/versions/{version}` | 该版本资源/字段快照及相邻上一版，未留存404 |
| `PUT /resources/{id}/fields/{fieldName}` | 携带字段读取时的`resource_version`，人工维护字段业务属性 |
| `GET /resources/{id}/schema-comparison/scans?limit=20&offset=0` | 登记扫描之后的同来源成功候选任务，返回`items,total` |
| `GET /resources/{id}/schema-comparison?scanTaskId=...` | 与登记扫描只读比较，返回字段及表注释差异、统计或未知范围 |

结构比较接口已于2026-10-07完成，详细协议和错误见[结构比较接口](SCHEMA_COMPARISON_API.md)。基准固定资源`scan_task_id`，同一只读事务读取持久快照，不查询业务源、不更新资源字段/版本/能力/策略；未发现目标表或范围无法确认不等于全部字段删除。

资源版本历史已于2026-10-09完成，见[版本历史协议](RESOURCE_HISTORY_API.md)。V11只回填存量当前基线；新登记、信息修改、字段维护和发布与快照同事务，失败整笔回滚。现有请求/版本参数不变，历史没有恢复或结构应用接口。

扫描只读取 Source 的 `information_schema`，Foundation 库持久化扫描任务、表名、字段名、类型、注释等结构信息，不读取或复制业务明细行。任务为同步执行，连接/权限问题会返回 `FAILED` 状态及不含地址、账号或密码的安全原因。估算行数来自 MySQL 元数据，不保证精确。重复扫描产生新的任务历史；同一数据源的同一表只能登记一次 Resource。

删除只用于清理误建或无引用草稿：运行中的扫描任务、已被资源引用的任务和已发布资源不能删除。已发布资源先下架再退役，保留治理历史和唯一登记。

任务响应包含 `table_count`、`field_count`、开始/完成时间和安全的 `failure_reason`（对应错误说明）。停用数据源的扫描请求返回 HTTP 400，不创建新任务。当前同步实现直接经历 RUNNING → SUCCESS/FAILED，PENDING 作为后续异步任务的预留状态，不伪造后台排队。中文页面展示字段数量、估算记录数、扫描状态、失败原因和字段顺序，任务间切换会清空旧结果，避免混淆不同来源。

资源创建示例（`scan_task_id`必填，使用扫描接口返回的实际编号；来源、模式及表必须属于该任务。下列占位编号需替换；`source_name`不作为权威值）：

```json
{
  "resource_name": "广州港集装箱作业事件数据集",
  "source_id": "SRC_实际ID",
  "scan_task_id": "SCAN_实际扫描ID",
  "schema_name": "port_source_db",
  "physical_table": "container_event",
  "resource_type": "TABLE",
  "business_description": "人工确认的作业事件业务含义",
  "owner_department": "数据管理部",
  "security_level": "内部",
  "update_mode": "实时"
}
```

字段编辑示例（`resource_version`取该字段列表响应的实际值；示例中的1需按当前值替换）：

```json
{"business_name":"事件发生时间","business_description":"作业发生时刻","time_field":true,"sensitivity_level":"内部","resource_version":1}
```

资源名称、业务说明、责任单位、安全等级和更新方式必须人工填写；扫描不会自动推断治理属性。Resource 发布只改变目录状态，不创建数据复制任务或 Source → Demand 数据通道。已发布资源可按 [Capability 接口](CAPABILITY_API.md) 关联能力；V0.2已支持现有REST查询的真实验证与启停、Kafka生产和Topic验证，其他运行时能力尚未实现。

## 前端登记、维护与发布

创建弹窗先通过任务详情/候选表接口核对网址中的任务、来源、模式及物理表，来源名称取任务响应。核对失败可重试，未核对不能保存；目录已登记表提示查看已有资源。2026-10-06保存请求新增`scan_task_id`，后端锁定并校验该任务为同来源的成功任务及对应表，严格从该快照复制字段；存在更新扫描也不切换。字段数量不完整则资源和字段一起回滚，遗漏/无效/失败/已删除/错配任务返回400，不回退最新任务。登记和删除先锁同一扫描任务，防止删除期间复制到残缺快照；资源绑定后该扫描不能删除。见[扫描快照绑定交付记录](RESOURCE_SCAN_SNAPSHOT_CHANGELOG.md)。

资源列表、详情、创建/编辑响应新增`scan_task_id`。详情基本信息提供“扫描来源”入口，可打开对应任务。创建客户端必须更新请求；普通编辑兼容不提供扫描编号，原绑定保持不变，提供不同任务则拒绝。编辑必须提供读取时的`version`，详见下节。数据库沿用V3已有扫描外键和版本列，无新增迁移，也不重新绑定存量资源。同来源/模式/表唯一约束保持不变。

### 资源与字段编辑冲突保护（2026-10-06）

- `POST /resources`不要求版本；创建后初始版本为1。
- `PUT /resources/{id}`必须提供正整数`version`，取列表或详情读取时的值，不取提交前临时获取的新值。扫描编号可省略，原绑定保持不变。
- 字段列表及字段保存响应新增正整数`resource_version`，表示该字段属性读取时所属资源的版本；字段与版本通过同一SQL查询读取。`PUT .../fields/{fieldName}`必须携带这个值。
- 资源业务信息、任意字段编辑成功均使同一资源版本加1。对不同字段的编辑也会互相冲突；这是资源整体的一致性保护，不是每字段独立版本。
- 后端先锁资源父记录，再核对预期版本，并在同一事务内更新。版本过期返回HTTP **409**、`code=10009`、`data=null`；本次字段/资源修改与版本增长均不提交。遗漏/非正版本返回400，资源或字段不存在返回404。
- 2026-10-17起，首次发布及草稿删除同样要求读取时版本，发布另要求原因。下架、重新发布和退役见下节；旧客户端须同步升级。
- 前端409后保留输入、禁止继续盲目保存，提供“取消并刷新目录/详情”。该操作关闭表单并读取最新信息，重新打开编辑后人工决定修改；不会自动换版本重发。网络失败保留原处理，结果未确认时先刷新核对；已提交但响应丢失的旧版本再次提交也会拒绝。

**接口兼容性：** 旧资源编辑客户端需补`version`，旧字段编辑客户端需补`resource_version`；不能继续无条件覆盖。前端、演示数据及现有真实联调脚本已同步。该阶段没有数据库迁移；后续已补版本历史、只读结构比较及生命周期，仍无自动合并。详见[并发编辑交付记录](RESOURCE_EDIT_CONCURRENCY_CHANGELOG.md)。

资源详情工作台使用既有详情、字段及关联能力接口：字段按关键词、主键/时间标记、敏感等级组合检索，能力按关键词/类型/状态/健康筛选，10/20/50项显示分页。字段与能力独立读取/重试，慢请求不阻断另一区域；错配、重复编号或真实/演示模式不一致的结果拒绝展示。字段保存锁定输入并只提交4项业务属性及读取时的`resource_version`；切换资源后旧读取、保存和发布响应不覆盖新页面。管理能力入口携带资源编号，注册仍要求已发布。未新增后端搜索/分页接口，字段版本读取与提交规则见上节；原工作台交付见[资源详情交付记录](RESOURCE_DETAIL_CHANGELOG.md)。

扫描工作台通过现有任务和数据源接口分页读取，每类最多5,000项，范围不完整有提示；任务支持关键词/来源/状态组合筛选和10/20/50项显示分页，表和字段支持结构检索。刷新会重新加载所选任务状态和结果；`?task=...`支持同页面更新，列表范围外的指定任务通过已有详情接口单独读取。表/字段故障可分别重试，旧响应不能覆盖新结果。默认真实扫描读取失败不切演示，扫描结果未确认时提示刷新检查且不自动重发；只有已启用来源才能发起扫描。同步后端流程保持不变，见[扫描工作台交付记录](SCAN_WORKBENCH_CHANGELOG.md)。

资源目录通过已有`limit/offset`接口分页读取，不增加后端搜索接口。关键词检索名称/编号/物理表/来源/责任单位，可组合来源、状态和安全等级，显示分页为10/20/50条。条件写入网址并在刷新和详情返回时恢复；每次最多读取5,000项，范围不完整有提示，检索只涵盖已读取元数据。分页中途失败或曾展示真实目录后的刷新失败显示错误，不切换成演示目录。见[目录交付记录](RESOURCE_CATALOG_CHANGELOG.md)。

资源目录的“从扫描结果创建资源”进入`/scans`。选择成功任务中的表后，来源系统、数据库模式和物理表自动带出且只读；编辑资源也不能改变这些来源字段。业务名称、说明、责任单位、安全等级和更新方式由人工填写，客户端校验位于`src/utils/resourceForm.js`，服务端校验仍由现有ResourceRequest负责。

详情页可维护字段业务属性，并直接发布草稿。字段名、类型、主键和技术注释仍来自扫描，编辑时只提交业务名称、描述、时间标记和敏感等级。保存后重新读取真实字段与资源版本；已发布才开放登记能力入口。发布返回的资源编号显示在详情和成功提示中，字段表新增业务描述展示。

真实资源保存、发布和字段编辑请求失败不会转换成模拟成功；弹窗保留输入，超时提示结果尚未确认，应刷新后检查实际状态。网络响应丢失时可能已在服务端提交，前端不会自动重发。资源详情的字段/能力读取失败按区域显示错误，不拿演示字段替代；404显示资源不存在。刷新不会更改后端数据。

目录列表在后端不可用时仍可显示有标记的演示数据；只有浏览器已有的演示来源/资源或显式全局演示模式可执行模拟操作。演示字段集中维护在`src/mock/demoData.js`，按资源编号分别存储，编辑一项资源不会改变其他资源或扫描字段。

扫描表与字段查询也按实际任务读取。切换任务会清空旧字段并关闭抽屉；此前请求稍后返回时被忽略，避免从旧结果创建错误来源的资源。创建入口绑定当前任务，抽屉入口绑定展示字段所属任务。

## 资源生命周期（2026-10-17，V20）

下列路径均以`/api/v1`为前缀，统一返回`{code,message,data}`。管理员或所属提供方可调用；需求方403，未登录401，无归属资源仅管理员操作。

| 接口 | 请求 | 成功data |
|---|---|---|
| GET `/resources/{id}/lifecycle-impact` | 无 | 影响对象 |
| POST `/resources/{id}/publish` | `version`、`reason` | 资源对象，保留原响应结构 |
| POST `/resources/{id}/unpublish` | 同上 | `{resource,impact}` |
| POST `/resources/{id}/republish` | 同上 | `{resource,impact}` |
| POST `/resources/{id}/retire` | 同上 | `{resource,impact}` |
| DELETE `/resources/{id}?version=读取版本` | 无请求体 | 原删除响应 |

写入示例：`{"version":2,"reason":"暂停共享，核对业务登记"}`。缺版本、空白原因、超过500字符、非法迁移返回400；过期版本或数据库并发冲突409/code10009，未知资源404。状态变更成功版本加1，同事务保存原因及真实历史操作人。不要自动读取新版本重发。草稿删除无需原因，但必须无能力关联。

影响对象：`resource_id,resource_version,status,capabilities,active_rest_relationships,kafka_executions,kafka_revoke_pending,can_delete`。`active_rest_relationships`统计登记状态为ACTIVE、此次下架将暂停的关系（不等同于瞬时有效调用数）；`kafka_executions`统计尚未实际REVOKED的身份，包含待撤回；`kafka_revoke_pending`统计撤权意图尚未完成的身份。预览不接受客户端对象列表，提交时重新锁定核对。

DRAFT仅首次发布；PUBLISHED仅下架；OFFLINE可重新发布或退役；RETIRED只读。发布校验启用来源、必填信息和已保存字段快照，不访问业务源。下架暂停REST、清除Kafka待领取密码及摘要令牌并保存撤权意图；退役终止剩余REST关系/Kafka申请；关联能力登记状态不变。重新发布不自动恢复任何共享。

历史列表及详情新增`operation_reason`、`operator_name`，动作新增`UNPUBLISH/REPUBLISH/RETIRE`；旧历史不补原因、不重写操作人。Kafka执行在资源事务提交后异步处理；Broker故障时资源保持下架/退役、待撤权持续重试，不报告消费已全部停止。手动恢复及操作路径见[生命周期指南](RESOURCE_LIFECYCLE_GUIDE.md)。
