# 资源版本历史接口

2026-10-17更新：V20新增生命周期操作原因（`operation_reason`），列表/详情同时返回已有真实操作人（`operator_name`）；动作包含`UNPUBLISH/REPUBLISH/RETIRE`。资源状态、版本及快照同事务提交，旧历史不回写或补造操作人/原因。退役保留全部版本。见[生命周期接口](SCAN_RESOURCE_API.md#资源生命周期2026-10-17v20)。以下为原接口基础约定。

前缀`/api/v1`，统一响应`{code,message,data}`。只留存资源登记信息和资源字段，不存业务行、数据库连接配置或凭据。现有资源编辑/字段维护的版本参数与响应不变。

## 留存规则

| 操作 | action | 留存时机 |
|---|---|---|
| 启用功能时已有资源 | `BASELINE` | V11迁移留当前版本，不增加资源版本，不重建更早记录 |
| 新资源登记 | `CREATE` | 字段复制完整后留V1 |
| 资源信息修改 | `RESOURCE_UPDATE` | 保存信息并增加版本后，留该版本全部资源及字段 |
| 字段业务属性修改 | `FIELD_UPDATE` | 增加资源版本后留完整快照，记录`changed_field` |
| 发布 | `PUBLISH` | 状态更新、版本增加后留完整快照 |

资源写入与快照插入在同一事务中，继续先锁资源父记录；快照失败整笔回滚，过期版本409不会新增历史。快照时间为实际留存UTC时间；资源自己的创建/更新时间是快照内的业务元数据，不能代替留存时间。

新增表`foundation_db.resource_revision`，以资源编号和版本为联合主键，存操作、修改字段、时间及两份JSON快照。全部7个字段有中文注释。没有修改/删除单条历史的接口；现有受约束的草稿删除会连同该资源历史清理，已发布资源仍不能删除。因此这是资源维护历史，不是永久删除审计。

## 读取接口

| 请求 | 返回 |
|---|---|
| `GET /resources/{id}/versions?limit=20&offset=0` | `{items,total}`，按版本倒序；默认每页20，limit 1–200，offset 0–1000000 |
| `GET /resources/{id}/versions/{version}` | `{snapshot,previous_snapshot}`，version为正整数；同一只读可重复读事务读取 |

列表元素为：

```json
{
  "resource_id": "RES_实际编号",
  "version": 3,
  "action": "FIELD_UPDATE",
  "changed_field": "event_time",
  "recorded_at": "2026-10-09T02:00:00.000"
}
```

`snapshot`包含`entry`（同列表元素）、`resource`（当时完整资源响应）、`fields`（当时全部资源字段响应，按字段顺序排列）。字段的`resource_version`与快照版本相同。资源信息包括当时看到的来源名称；来源后续重命名不会覆盖旧快照。

`previous_snapshot`仅返回相邻的`version-1`，未留存则为`null`。不拿更早可用记录当作上一次操作，不补造缺失版本。未知资源或未留存版本404，非正版本/非法分页400，损坏快照返回错误，不用当前资源替代旧内容。

快照字段范围为既有`resource_field`属性：字段名、完整数据类型、主键、技术注释、顺序、业务名称/说明、时间字段标记、敏感等级和读取版本。扫描的可空/默认值仍由登记扫描与结构比较接口提供，不给历史资源字段臆造这些属性。Capability及共享关系/策略不随资源版本保存；各自版本机制保持不变，不宣称这是完整共享治理版本快照。

## 前端

“资源详情 → 版本历史”按需加载，每页20项；默认查看当前页最新版本。显示留存时间、操作类型、修改字段、当时的资源信息和字段快照；与相邻版本比较业务属性和状态，忽略仅用于计数/时间的版本及更新时间。首次基线明确标记“更早版本未留存”，没有上一版不显示“无变化”。字段快照可检索并按10/20/50项分页。

读取失败清空旧内容，刷新列表或重试快照；切换版本/资源/页签后忽略晚到响应。真实失败不回退演示成功。显式演示资源通过`src/mock/resourceVersionData.js`保留独立快照，旧浏览器数据只提供当前基线，不推测更早版本。

无恢复版本、结构应用或版本审批。登录身份认证已由后续三角色改造实现，新历史使用服务端真实身份；旧历史保持原样。本轮生命周期保留能力登记及策略内容，也不修改业务源数据。
