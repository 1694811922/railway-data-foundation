# 资源生命周期使用指南

## 操作入口与规则

管理员可管理全部资源；提供方只能管理归属本主体的资源。无归属的旧资源仍仅管理员管理，不自动分配。需求方公开目录只展示已发布资源，本人的申请、历史接收数据和下载入口继续保留。

在“资源目录 → 更多操作”或“资源详情”选择状态操作，先核对关联影响，再填写原因并确认。

| 当前状态 | 允许操作 | 说明 |
|---|---|---|
| 草稿 | 编辑、发布、删除草稿 | 无关联能力才可删除 |
| 已发布 | 编辑、下架 | 下架暂停REST共享，持久登记Kafka撤权意图 |
| 已下架 | 编辑、重新发布、退役 | 重新发布不恢复原共享权限 |
| 已退役 | 查看信息、字段、能力和历史 | 不可恢复、编辑或物理删除 |

草稿删除仅清理底座登记、字段及对应版本快照，不删除源表。退役必须先下架，保留编号、字段、关联能力、共享记录和版本历史；同来源、模式、物理表的唯一登记继续占用。状态操作不修改源业务表或需求方已接收数据。

## 下架后如何恢复共享

下架保留原审批、策略及REST调用凭据。关联能力的登记状态不变，实际访问仍必须满足父资源已发布等治理条件。下架期间不能新建/审批启用共享、配置Kafka订阅或取得生产准入。

重新发布后，由管理员分别处理：

1. REST：在共享关系中手动“启用”。仍校验原审批、有效期、主体、来源、资源、能力及策略，不能借恢复绕过原限制。
2. Kafka：等待旧身份实际撤权完成，在订阅授权中重新配置。需求方领取新凭据，进入已有接收任务，停止并等待连接释放、更新凭据，再手动恢复。沿用保存的检查点，不重建任务或清除历史消息。

旧Kafka身份和技术摘要令牌不会因为重新发布恢复。即使迅速下架再发布，已保存的撤权意图仍继续执行。

## 如何判断撤权是否完成

状态操作结果和详情页会单独显示“权限撤回待完成”；管理员可进入Kafka订阅处理页，提供方不能代替管理员执行配置。刷新权限状态可重新核对。

资源下架成功只表示数据库治理状态已提交。Broker不可用时，撤权执行器保留意图并重试，不能宣称所有直接Kafka客户端已停止。已通过校验的在途操作可能完成；Broker实际移除身份和ACL后，直接客户端才失去对应权限。底座不可用时独立接收服务按原规则阻塞，但这不等于底座能强制停止所有外部客户端。

## 冲突与失败

发布、下架、重新发布、退役必须提交页面读取时的版本和原因。草稿删除也必须携带读取版本。版本过期返回409，关闭对话框、刷新、重新核对后再操作，不自动重试写入。普通失败保留原因；超时或回执不确定时先刷新确认实际状态。

发布只校验启用来源、必填登记信息和已保存字段快照，不重新扫描、连接业务源或变更来源绑定。版本历史展示状态操作、原因和真实操作人；旧历史缺少原因时显示未记录，不补造。

## 升级与边界

本轮底座追加Flyway V20，保留数据与旧版本记录。提供方和需求方无新增数据库迁移；需求方仍V4。先更新底座，再更新前端；旧客户端的无版本发布/删除请求需同步升级。无需更换已有密钥、密码或重新初始化数据库。

显式演示仅操作独立前端样例，不发真实授权请求，也不伪造Broker撤权。真实失败不会转演示成功。本轮没有结构变更应用、版本回滚、CDC或云端部署。
