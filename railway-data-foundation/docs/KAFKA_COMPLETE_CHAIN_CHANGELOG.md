# Kafka 完整链路联调与生产记录定位

日期：2026-10-09。V0.5 提供侧验证补充；不包含需求方订阅授权工作流。

## 本轮完成

1. `kafka-runtime` 增加所属 `resource_id`。提供服务完成能力、类型、来源、Topic与认证核对后，将底座返回的能力/资源编号写入生产摘要；不采信调用方自报的资源/需求方编号。资源编号缺失或格式错误按控制信息不可用拒绝发送。
2. 成功生产记录可在“调用审计、调用追踪、共享计量”按资源或能力定位。需求方、共享关系和访问策略保持空值，因为运维生产不是需求方的受控业务消费；不伪造订阅身份。
3. 监管页使用“记录数、字节数”标题。接口查询与消息生产仍分开统计，生产成功不代表需求方收到或处理完毕。
4. 新增可重复运行的完整链路验证：真实 MySQL 元数据、真实底座和提供服务进程、真实 SCRAM Kafka、真实浏览器操作，不拦截启停成功、不回退演示数据。

## 验证环境

- `foundation_kafka_live_test`：独立底座测试库，使用现有V1至V11迁移，没有新增生产表。临时来源、扫描、资源、字段、版本、能力与运行记录在结束时按随机测试身份清理；保留空测试库便于复验，不执行全库删除。
- Source：只读访问原本机 `port_source_db.container_event` 的模拟事件，仍为20条。提供服务与扫描均使用只读账号，不改变表结构或原业务行。
- Kafka：随机端口的临时KRaft Broker、随机主题与独立账号。底座账号仅描述指定主题，生产账号仅具备生产所需权限；使用独立SCRAM-SHA-512认证。
- 临时测试订阅账号默认无读取权限，先验证拒绝，再由测试夹具显式授予精确主题/消费组权限来核对一条消息，结束撤销。不登记任何真实需求方共享关系，不扩展REST字段/时间策略。
- 外部监听和控制器监听均仅环回。匿名控制器超级用户只属于隔离测试，不能复制到正式部署。测试不验证远程TLS部署，正式连接仍要求SASL_SSL。

## 实际验收

- 前端真实执行：草稿拒绝发送 → 验证成功 → 启用 → 实际生产回执 → 停用后403 → 再验证保持停用 → 来源停用后403。
- 缺少能力编号400、错误运维身份403；实际停止底座后新发送503。
- Broker只新增一条消息；被拒绝的尝试不增加位点。
- 生产回执与临时消费者读取的主题、分区、位点逐项一致；载荷字节与自动摘要一致，本次为1条、320字节。
- 自动审计/追踪落库，并在真实浏览器展示；全局及按资源的消息计量均为1条、320字节，不计为接口调用量。
- 资源版本与字段属性前后相同。Source仍20条，开发库仍V11，两套开发服务不被测试夹具停止或替换。
- 完整后端127项通过；独立Kafka权限测试13项通过（完整链路测试默认跳过，单独显式执行通过1项）；前端111项和构建通过。

## 如何复验

先启动本地MySQL、安装前端依赖，在项目目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./scripts/test-kafka-foundation-live.ps1 -Offline
```

如果Node不在PATH，加 `-NodeExecutable '实际node.exe的绝对路径'`。脚本导入本机环境但不输出秘密，创建独立测试库，编译现有服务并准备运行依赖；以独立端口和明确的环境白名单启动测试服务，不覆盖开发服务正在使用的JAR，也不修改 `.env.local` 的Kafka配置。

Java父进程只向各子进程注入其所需凭据。浏览器测试进程仅得到测试运维令牌，没有Source或底座数据库密码；令牌不会写入文件、命令行或截图。结束停止自建的服务、浏览器与Broker，清理测试元数据。

运行证据保存在被Git忽略的 `.runtime/kafka-chain-*/`：启用/停用/真实审计截图、无业务载荷的回执/计量验证JSON及服务日志。截图不包含源业务行或密码；Source模拟事件由提供服务直读并发送到临时Broker，测试不把消息载荷写入底座、日志或证据文件。
