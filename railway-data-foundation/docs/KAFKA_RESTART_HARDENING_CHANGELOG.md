# Kafka 本地重启与配置保护完善

日期：2026-10-11。本轮继续完善本地实验可靠性，没有改动业务接口、数据库结构或前端页面，没有安装WSL或修改Windows可选功能。

## 结果与限制

历史订阅身份认证失败在本轮复验中暂未复现，失败日志继续保留，**尚未确认该历史失败的根因**。不能将复验通过写成所有认证问题已解决。

启动脚本原先会在每次启动时重新写入固定账号的SCRAM凭据与ACL，本轮改为首次初始化与正常启动分开：只有本次刚格式化的新集群允许初始化；已有集群只核对账号、原密码认证、精确权限、主题和集群编号。缺少后端覆盖配置时拒绝启动，不重新格式化或静默重发凭据。

Windows在线删除主题导致日志文件占用和Broker退出的历史问题仍然存在。当前仍禁用在线删除，测试结束撤销临时账号与权限，保留测试主题及清单；本轮结果只作为本机实验回归，不计为稳定部署或高可用验收。Linux环境尚未选择。

## 重启测试操作链

1. 创建独立随机主题、订阅账号、消费组和三条合成消息，原`container_event`不修改。
2. 核对账号机制、精确权限和主题；错误密码必须被真实Kafka认证拒绝，超时不能算拒绝成功。
3. 重启前读取偏移0，明确提交下一偏移1。
4. 第一次正常停止、启动，使用原凭据核对并读取偏移1，提交下一偏移2。
5. 第二次正常停止、启动，使用同一凭据读取偏移2，提交下一偏移3。
6. 使用同集群编号的独立元信息副本测试缺失覆盖配置保护，不移动实际配置；原身份文件与覆盖配置摘要必须保持不变。
7. 撤销该测试账号与权限；Windows保留主题并记录准确名称，不宣称消息已清理。

测试没有重新创建订阅账号、重发订阅密码或把消费进度改回起点。默认`-Rounds 2`，可用`-Rounds 1`缩短验证。已有未完成检查点时拒绝覆盖，先诊断该检查点。

```powershell
cd railway-data-foundation
./scripts/test-local-kafka.ps1 -Offline
./scripts/test-local-kafka-bootstrap.ps1
```
