# V0.3 调用凭据与REST访问校验交付记录

日期：2026-10-04。

## 交付行为

之前Provider仅按能力编号检查V0.2运行状态，共享关系登记与撤回尚未控制实际查询。现在GET必须携带需求方调用令牌、共享关系编号与能力编号，Provider逐次向Foundation请求决策，按允许字段及数据时间范围读取Source。旧的能力编号单独调用不再有效。

- V9新增调用凭据和凭据历史表，全部字段有中文注释；既有迁移未修改。
- 随机256位调用令牌绑定已启用需求方，只展示一次，数据库保存摘要；可到期、撤销并保留历史。
- 底座联合检查身份、双方主体、关系确认/状态/有效期、资源/能力/来源及策略，不读取业务行。
- 提供服务只查询授权字段，在SQL中执行数据时间过滤；筛选参数涉及的字段也须授权。
- 治理时间按UTC，源库默认+08:00；查询输入需带时区，返回源库时间带偏移。
- 前端“调用凭据”和“共享调用验证”已接入路由与菜单。令牌不写浏览器存储或自动复制；退出页面清除，旧响应不能覆盖新页面。
- 真实拒绝或故障不模拟成功。共享调用页更改输入后清除旧结果；返回列不符合本次请求时不展示业务记录。
- 调用说明保留原接口字段，追加三个必带头及授权提示；可复制命令使用占位变量，不嵌入真实令牌。
- 能力验证及启用探测要求共享运行时版本标识，缺少该标识的旧Provider不能通过本阶段的验证/启用检查。
- Provider与Foundation使用后端服务间凭据，本机脚本生成并保留于被忽略的.env.local；Kafka手动生产入口仅允许运维凭据触发。

## 当前边界

- 已完成固定container_event的REST授权闭环，Provider仍绑定一个来源。
- 每次检查当前治理状态，不缓存允许结果；暂停、撤回或凭据撤销提交后拒绝新请求，已通过检查的在途请求可能完成。
- 关系操作历史与凭据历史不等于V0.4业务调用审计；审计、调用链和共享计量尚未实现。
- Kafka Topic消费授权、Kafka启停、CDC和只读模板执行仍未实现。
- 管理端没有服务端管理员登录与角色权限，仍为本机原型；独立需求方服务未实现，共享调用页由管理员模拟需求方。
