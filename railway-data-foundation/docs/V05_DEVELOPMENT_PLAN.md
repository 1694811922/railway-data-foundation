## 第一阶段实现范围

新增 `examples/rest-demand/` 与两个 PowerShell 启动/验证脚本，复用既有 API。该调用方只持有需求方令牌和关系/能力编号，不持有 Source 密码或提供侧服务间凭据。提供服务在每次查询中重新授权、参数化读取源库；底座接收提供侧实际操作摘要。

调用说明是地址发现，不是权限证明；客户端将目标限定为显式配置的提供方地址，拒绝重定向、未启用能力、协议异常及真实失败，不自动重试。顺序有限分页仅服务联调，不宣称持续消费、跨页一致性或恰好一次交付。

本轮不新增后端模块、数据库迁移、前端管理业务或需求方常驻服务。`demand-service/` 仍为预留目录。具体接入步骤见 [REST 接入规范](DEMAND_REST_INTEGRATION.md)。

## 后续阶段约束

Kafka 阶段须先确定可验证的 Broker 权限执行方式、运行环境和凭据隔离；当前运维生产触发接口不能充当需求方订阅授权。底座可管理治理元信息，但不能通过登记关系就宣称 Broker 已执行权限。

CDC 在 Kafka 治理链路稳定后接入，优先使用外部组件适配。资源结构人工更新属于后续 V1.0 资源治理完善，可独立推进，不作为进入 V0.5 的前置条件。

V0.4 当前仅提供侧自动摘要；消费侧采集、多节点鉴权及完整分布式追踪仍单独列为未完成。阶段验收必须区分接入示例可运行与完整业务消费系统已实现。
