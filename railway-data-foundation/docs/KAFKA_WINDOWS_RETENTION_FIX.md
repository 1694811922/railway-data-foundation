# 本机 Kafka 消息过期清理故障修复

日期：2026-10-12。

## 故障与处理

17:57:06，旧实验主题 `rdlab_302782b9bf4b42c4a4547bf7faf9d6ca` 的索引文件在改名为 `.deleted` 时出现Windows文件占用错误，Kafka随后报告全部日志目录失败并退出。两个业务后端正常，但能力验证连接19092超时。主题登记 `port.container.event.v1` 没有拼写错误。

修改 `scripts/start-local-kafka.ps1`：取消原24小时过期，普通主题默认时间和容量保留均为无限。`scripts/java/LocalKafka.java` 增加只读 `retention-check`，使用原有运维身份、校验集群编号并检查所有普通主题的有效保留配置；不改主题、账号、权限或消费位点。已有有限保留的覆盖配置不自动改写，核对失败不能报启动成功。

Kafka官方说明：[`log.retention.ms=-1` 不设时间限制](https://kafka.apache.org/39/configuration/broker-configs/)；[主题级保留配置可能覆盖服务端默认值](https://kafka.apache.org/39/configuration/topic-level-configs/)。本措施规避此次过期清理路径，不修复Kafka/Windows文件映射与文件锁机制。

## 使用与限制

两个后端已经加载Kafka配置时，仅恢复Kafka即可，无需重新登录或重启两个后端。在接口能力页重新点击“验证”；页面状态必须以真实接口结果为准，不直接写数据库为成功。

新启动继续使用VS Code“运行和调试”中的含Kafka入口。正常停止使用现有停止脚本，不删除日志目录、不重新格式化。无限保留会增加磁盘占用；本修复不涵盖在线删主题、内部主题压缩、多节点、生产部署或长期稳定性。不要在Windows运行目录存放重要业务消息。
