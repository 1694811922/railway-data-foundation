# Kafka 订阅与数据接收联动

## 使用方法

1. 需求方登录，进入“我的 Kafka 订阅”，点击对应申请的“数据接收”。
2. 已有接收任务时，直接打开该任务及已落库消息，不重新填写密码或技术令牌。
3. 尚无任务时，只有当前授权实际有效才显示创建表单。填写已领取的专属密码和技术令牌，创建后自行启动；本入口不自动启动、恢复或重置消费位置。
4. 查看数据后关闭抽屉，可操作该任务的接收进度、停止、启动或恢复；“查看全部任务”返回本主体完整任务列表。

也可从“数据接收 → 创建接收任务”选择订阅。选择已有任务的订阅时会直接打开现有任务。关联查询期间禁止保存，读取失败显示“重试关联”，不会把故障解释为没有任务。

领取凭据后的“配置接收任务”仍只在内存中转交一次凭据。已有任务或关联失败时清除该临时凭据，不覆盖接收服务保存的配置；需要更新配置时先停止任务，使用原有“更新凭据”操作。

## 历史数据与权限

撤权、到期或阻塞的订阅也可通过此入口打开已有任务及历史接收数据。历史读取由有效登录身份和任务主体归属控制，不要求 Kafka 授权仍有效；启动、恢复和接收进度仍按原规则重新核验授权。

管理员、提供方没有此入口或业务消息权限。伪造其他主体的授权编号不会返回其任务或总数；后续订阅详情也由底座检查主体权限。普通查询不返回密码、技术令牌或完整连接配置。

切换订阅、返回全部任务、退出或更换身份时清空旧页面内容。晚到的关联、数据和文件响应不能打开旧任务或下载旧文件。显式演示模式不执行真实关联查询或创建。

## 接口变更

需求方服务的现有列表增加可选参数：

```http
GET /demand/api/v1/receiving-tasks?grantId=KSG_<32位小写十六进制>&limit=1&offset=0
```

`grantId`精确匹配，与`keyword`组合取交集；列表和总数同时按真实登录主体过滤，在同一只读可重复读事务内读取。参数缺省时保留原列表行为；空值、通配符或格式错误返回400。未知或其他主体编号返回本主体范围内的空列表，不披露编号是否存在。

响应保持`{code,message,data:{items,total}}`，沿用`/demand`直接路由到18082。底座不转发业务消息，不新建数据库表，不修改原授权、任务、检查点或源业务表。

## 启动

沿用项目现有启动方式，启动 MySQL、Kafka、foundation-service（18080）、provider-service（18081）、demand-service（18082），前端在`foundation-web`执行`npm run dev`。只浏览已有历史消息不需要 Kafka 可用，但需要底座验证真实登录与主体状态。

本轮保留一个授权最多一个任务的限制，没有删除接收任务、后台导出或任意业务表映射。
