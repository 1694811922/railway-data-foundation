# 统一传输监测交付记录

日期：2026-10-16。本轮按用户确认的单页、单表方案实施，替代此前管理员四个独立监管菜单及REST/Kafka主页签方案。

## 最终功能

- 管理员仅保留“运行监管 → 传输监测”。REST接口和Kafka消息同表，支持时间、资源、方式、阶段、结果以及任务/追踪编号筛选；默认当天，每页10/20/50条。
- 四张统计卡分别显示REST调用次数、Kafka发送成功消息数、接收新增落库条数、异常事件数。统计按时间及资源汇总完整记录，其他列表筛选不改变统计，未上报未知。
- 详情抽屉展示固定原因、批次、主题、分区位置、已有追踪及耗时范围；采集状态和逐授权消费摘要收进独立抽屉，保留异常提示。原地址兼容跳转。
- 提供方发送记录与需求方任务日志保留；提供方已有REST记录权限不变。新统一接口仅管理员，401/403及原主体隔离不放宽。

## 主要文件与接口

| 文件/组件 | 作用 |
|---|---|
| `TransferMonitorController/Service` | `GET /api/v1/transfer-monitor/events`，只读事务内SQL合并、稳定排序、跨来源分页与完整统计；限定24小时，不读取业务内容 |
| 底座 `V19__receiver_storage_duration.sql` | 接收技术事件新增可空批次入库耗时，中文注释 |
| 需求方 `V4__storage_duration.sql` | 本地技术日志新增同一可空字段，不改消息或业务源表 |
| `ReceivingWorkers`、`DurableInbox` | 用单调时钟测量批次事务开始至提交返回，在同批次位置回执中持久写入；回执缺失时保持未知 |
| `MonitorReporter`、`ReceiverMonitorRequest/Service` | 白名单携带可选耗时，仅位置回执允许携带；旧报告摘要不变，新内容冲突拒绝，不使用订阅凭据 |
| `TransferMonitorView.vue`、`transferMonitor.js` | 中文单页单表、统计、筛选分页、两个详情抽屉、错误清空/重试、定时刷新和响应隔离 |
| `workspace.js`、路由、`api/telemetry.js` | 单菜单、权限、旧路由兼容及新API封装 |

完整API字段、默认值和操作说明见[使用指南](TRANSFER_MONITOR_GUIDE.md)。底座V19、需求方V4，无新业务表、无新凭据。
