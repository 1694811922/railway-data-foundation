## 网页注册入口（2026-10-12新增）

启动新版后端及前端，打开 `http://127.0.0.1:5173/login`，点击“没有账号？注册账号”。本机没有管理员且开启本机初始化开关时，显示“初始化管理员”，填写账号、名称、密码及确认密码，创建后返回登录；密码由自己设置，不存在默认密码。

已有管理员后显示普通注册表单，申请角色仅为数据提供方或数据需求方，填写单位并提交。管理员登录“共享治理 → 用户账号 → 注册申请”，核实单位、选择已有同角色启用主体后通过，或填写原因拒绝。没有对应单位时先在“共享主体管理”登记；审核通过后申请人使用注册时的密码登录。不要将填写的单位名当作已认证的主体身份。

待审核账号不能登录；管理员网页初始化不能重置既有管理员。本机旧配置需显式设置 `FOUNDATION_REGISTRATION_LOCAL_BOOTSTRAP_ENABLED=true`，服务仍绑定127.0.0.1；远程部署/反向代理必须关闭，仍可使用下文安全初始化脚本。注册接口与限制见[注册说明](REGISTRATION_API.md)。下文历史“没有自助注册”的描述由本节替代。

更新：2026-10-10。一个 `foundation-web` 工程、同一个登录页和布局，菜单由服务端返回的真实身份决定，没有普通用户切换角色入口。

## 1. 启动与初始化

在VS Code打开项目，终端进入 `railway-data-foundation`。使用已有本机后端启动方式，或执行：

```powershell
./scripts/start-local.ps1 -Offline
```

首次使用新版账号体系时，在另一个终端安全初始化管理员：

```powershell
./scripts/initialize-admin.ps1 -Username foundation_admin
```

按终端提示自行设置密码，不回显，也不会保存到 `.env.local` 或仓库。脚本要求已经打包的新版Foundation；首次创建管理员后自动退出初始化进程。已有管理员时不会重置账号，不能将脚本当作密码恢复工具。不要把登录密码当作数据库密码、Provider控制令牌或Kafka订阅密码。

前端终端：

```powershell
cd foundation-web
npm install
npm run dev
```

访问终端给出的本机地址，通常为 `http://127.0.0.1:5173`。Foundation默认18080，Provider默认18081，MySQL本机默认13306。管理功能使用Foundation和MySQL；现有REST能力验证与外部数据查询需要Provider；实际Kafka权限配置/生产/消费需要另行配置的真实Broker及后端运维身份。正常开发环境没有自动常驻Kafka，权限执行默认关闭，不能只靠界面制造订阅成功。

如果使用VS Code既有运行/调试配置启动服务，也须先完成管理员初始化并使用真实账号登录。服务更新/重启后原会话失效，应重新登录。

## 2. 创建三个角色账号

1. 管理员登录，在“共享主体管理”创建启用的提供方、需求方单位。复用原主体，不再建立第二套单位表。
2. 在“用户账号”创建普通账号，选择数据提供方或数据需求方角色，并绑定对应类型的主体。密码由管理员设置并安全交付，不使用仓库公共密码。
3. 每个普通账号只关联一个主体；同一主体可以有多个账号。账号名/角色/主体绑定创建后不可修改，可停用或重置密码。
4. 可用浏览器独立用户配置或无痕窗口分别登录不同账号。界面顶部显示当前用户、角色和所属单位。

本轮自动测试使用随机账号密码和独立主体，测试结束已清理，不能拿测试账号直接登录开发环境。

### 管理员维护账号

进入“共享治理 → 用户账号”，按登录账号、用户名称、主体或单位检索，可筛选角色及启停状态，每页10/20/50项。分页总数来自后端；读取失败清空本页并显示“重试读取”，不会用演示账号补齐。

创建账号时填登录账号、用户名称、角色和初始密码。普通账号搜索已启用的同角色共享主体，下拉底部“加载更多主体”继续翻页；没有候选先去登记共享主体。密码至少12个Unicode字符，UTF-8编码不超过72字节，中文和表情均按字符及字节检查，不截断密码。管理员账号不绑定普通主体。

可停用、启用或重置其他账号密码；当前管理员账号改密使用顶部“修改密码”。提交期间操作锁定，取消/失败后清空密码；版本冲突后“关闭并刷新”，重新人工填写，不能自动换版本重发。网络失败导致结果不明时先关闭刷新核对，禁止重复提交。重置后旧登录会话下次请求失效；不修改外部REST凭据或Kafka身份。没有账号删除、角色更改或主体重新绑定入口。

### 修改自己的登录密码

三个角色登录后，点击顶部“修改密码”，输入当前密码、新密码及再次确认。新密码至少12个字符，UTF-8编码不超过72字节，不能与当前密码相同。保存成功后自动回到登录页，使用新密码重新登录；其他浏览器中的旧登录也会在下次请求时失效。

输入当前密码错误不会修改账号，关闭弹窗或失败后不会保留密码。网络中断时修改结果可能未确认，应重新登录核对；不会自动重复提交。这里只修改底座登录密码，不会重置REST调用令牌或Kafka订阅密码。显式演示模式不支持真实改密。忘记登录密码仍需管理员通过“用户账号”重置。

## 3. 角色功能

| 角色 | 菜单与操作 |
|---|---|
| 管理员 | 全平台接入、扫描、资源、能力、主体、账号；REST共享关系与策略审批、访问凭据；Kafka订阅审批、实际配置/停止/重试；统一传输监测、统计与技术详情 |
| 提供方 | 我的来源、扫描、资源/字段、结构比较与版本历史、接口能力；涉及本主体的REST/Kafka申请内容确认或退回、共享记录查询；本来源资源的运行摘要 |
| 需求方 | 公开已发布资源/字段与可用能力目录；本主体REST共享申请、Kafka整主题订阅申请；本主体审批/执行状态、访问凭据签发/撤销、Kafka一次性领取及停止/撤回；后台接收、任务日志及本主体数据下载 |

提供方不能管理其他提供方或无归属来源，不能最终审批。需求方不能改资源/能力或审批结果，不得访问源数据库账号、后台运行配置、他方申请或凭据。路由限制之外，服务端对实际编号、请求体关联编号和查询分页均检查。

## 4. 提供方资源登记链路

1. 提供方登录“我的数据源”，填写外部数据库连接配置和只读账号，保存后测试连接。服务端自动将新来源归属登录主体。
2. 执行扫描，在“元数据扫描”检查表和字段。
3. 从选中的成功扫描登记资源，补全业务含义、责任单位、安全等级等；人工核对字段并发布。
4. 如需在需求方目录展示，将资源安全等级设为“公开”，并保证来源启用；公开只涉及元数据展示，仍须单独共享授权。
5. 登记所属资源的接口能力，按现有支持范围验证并启用。需求方目录只展示已启用、最近验证UP的能力。
6. “共享申请与记录”查看涉及本主体的申请；现有流程没有提供方确认环节，本轮不提供确认按钮，管理员完成最终审批。

管理员也可新增来源并显式选择启用提供方。已有无归属数据不自动分给某单位，仍仅管理员管理；本轮没有提供方接管或存量归属转移入口。

## 5. REST共享演示链路

需求方目录 → 资源详情 → 申请REST共享 → 填写用途、有效期、允许字段和数据时间范围 → 保存并提交 → 管理员核对策略并确认/启用 → 需求方查看本主体状态、签发本主体访问凭据 → 外部程序访问Provider。

资源/提供方/需求方按真实关系绑定，需求方不能选择其他需求单位或编造资源归属。访问令牌只显示一次，不写浏览器持久存储。令牌本身不等于授权，还必须有有效启用共享关系；外部程序仍携带Bearer令牌、关系编号及能力编号。底座不代理查询结果、不保存业务明细。接入见 [外部REST指南](DEMAND_REST_INTEGRATION.md)。

## 6. Kafka整主题订阅演示链路

需求方目录 → Kafka能力 → 新建本主体订阅申请 → 明确接受完整消息和可访问历史 → 提交 → 管理员确认范围 → 管理员实际配置Broker权限 → 执行状态为已生效 → 需求方一次性领取专属Kafka身份和独立摘要令牌 → 外部消费者按固定主题/消费组读取并可选上报技术摘要 → 订阅详情查看消费观察 → 需求方停止或撤回 → 等待Broker已撤权。

“消费观察”展示外部程序自报条次和字节，未上报显示未知，涉及本主体的提供方与需求方可读，管理员可读全平台。摘要不包含业务消息；同一报告重试不重复计数，不同报告重读会再计。上报令牌与Kafka密码分别使用，只在领取弹窗内存显示，关闭清除；旧已领取订阅需停止、确认撤权后重新配置及领取才能获得摘要令牌，见 [摘要接口与限制](KAFKA_CONSUMPTION_API.md)。

“已确认”不等于Broker权限已生效。订阅密码只领取一次，响应丢失须撤权后重新配置；不保存在浏览器localStorage/sessionStorage。整主题授权不自动继承REST字段/时间投影。原Kafka撤权补偿、依赖失效协调及控制停机限制仍适用，见 [Kafka执行指南](KAFKA_SUBSCRIPTION_EXECUTION.md)。

## 7. 安全与当前限制

- 管理Cookie、REST调用令牌和Kafka身份是三种独立机制。停用登录账号不自动撤销外部凭据；需要按原授权流程撤销/停止，或停用对应共享主体。
- 公开元数据没有匿名访问入口，需求方登录后浏览。内部/敏感/机密资源不进入该角色目录。本轮没有单独可见性字段或公开范围审核流程。
- 会话只保存在单个Spring Boot进程，重启需重新登录；支持本人修改密码，没有单点登录、多角色账号、自助找回、账号绑定变更或归属转移。
- 结构变化应用/版本恢复、可信消费计费及CDC尚未实现；已实现提供方确认、接收落库及持久技术补报。
- 显式 `VITE_USE_MOCK=true` 为独立演示管理员模式，不能用于验证真实三角色权限；Axios禁止该模式实际请求真实后端。默认false，真实失败不会回退演示成功。
